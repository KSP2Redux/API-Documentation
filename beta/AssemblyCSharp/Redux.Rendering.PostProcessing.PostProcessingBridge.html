    Class PostProcessingBridge

    Renders the game's Post Processing Stack v2 data through URP.

    Inheritance
    object
    PostProcessingBridge
    Namespace: Redux.Rendering.PostProcessing
    Assembly: Ksp2Redux.dll
    Syntax
    public static class PostProcessingBridge
    Remarks

    The package was replaced by a data-only copy (Assets/ThirdParty/Unity.Postprocessing.Runtime), so stock bundles and game code keep using its volumes, profiles and layers. Before URP renders each frame this:

    • mirrors every enabled package volume as a URP UnityEngine.Rendering.Volume on the same GameObject, with a runtime profile converted by Redux.Rendering.PostProcessing.PostProcessProfileConverter and refreshed when the package settings change.
    • applies every enabled package layer to its camera's URP data: post-processing on, volume mask and trigger, and anti-aliasing (Redux.Rendering.PostProcessing.CameraMirror).
    • registers the render hooks for what URP lacks or renders differently: the NaN stop, depth of field, auto exposure, bloom, scalable ambient obscurance, the custom tone curve, the final pass (FXAA and dithering) and the KSP CRT vignette and tutorial overlay.
    • registers a default profile that gives URP's components the package's defaults.

    The hooks keep the package's order. Before URP post-processing: NaN stop, tutorial overlay (the package's before-stack effect), depth of field, auto exposure (histogram of the depth of field result, then the multiply), bloom (prefiltered from the exposed colour and added to it). URP's uber pass then grades. After it: custom tone curve (part of the package's grading), CRT vignette (an after-stack effect), final pass. Under HDR output the conversion to the display's nits comes last, after every overlay (Redux.Rendering.PostProcessing.HdrOutputHook).

    Outside play mode only objects that are not saved with a scene are mirrored, such as the planet authoring preview's camera layer and quick volume, so editing a scene never changes its saved camera data.
