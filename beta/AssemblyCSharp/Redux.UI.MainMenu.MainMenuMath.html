    Class MainMenuMath

    Everything the main menu works out for itself: which body a channel named, where a planet and a craft belong on screen, and the shapes they move along between one arrangement and the next.

    Inheritance
    object
    MainMenuMath
    Namespace: Redux.UI.MainMenu
    Assembly: Assembly-CSharp.dll
    Syntax
    public static class MainMenuMath
    Remarks

    The menu shows bodies and craft at whatever size and place suit the picture rather than at any scale the game already has an answer for, so all of this is its own problem. It lives together because it is the whole of what can be worked out without a scene to look at, which is also the whole of what can be tested without running the game.

    SolveBodyFramingScale(float, float)

    Solves how much to shrink a body so its terrain does not crowd the craft in front of it.

    Declaration
    public static float SolveBodyFramingScale(float extentUnits, float sphereRadiusUnits)
    Parameters
    Type Name Description
    float extentUnits

    How far the drawn body reaches from its centre, where it faces the craft.
    float sphereRadiusUnits

    How far the surface would reach with no terrain on it.
    Returns
    Type Description
    float

    What to multiply the body's scale by, which is one for a body that does not overhang its own sphere.
    Remarks

    Every body's surface sits at the same distance from its own centre in the mesh it is drawn from, so two bodies drawn side by side fill the frame the same way however large either of them really is. What breaks that is terrain: a mountain is a rounding error against a planet's radius and most of the body on a rock a mile across, and it is the drawn shape rather than the sphere under it that runs into the craft. Pulling the body back by exactly what it overhangs leaves a smooth one untouched and gives a lumpy one the same room in frame.

    The axis the camera turns about, which is the camera's own up.

    Remarks

    The camera turns the whole way round during a change, so there is no direction it does not sweep past except one: the axis it turns about.     SolveSunScale(double, double)

    Solves how much brighter or dimmer the sun is at one distance than at another.

    Declaration
    public static float SolveSunScale(double referenceRadiusMetres, double bodyRadiusMetres)
    Parameters
    Type Name Description
    double referenceRadiusMetres

    The distance the menu's own lighting was set up at.
    double bodyRadiusMetres

    The distance of the body being shown.
    Returns
    Type Description
    float

    What to multiply the menu's authored sun by, or one when either distance is missing, which leaves the sun exactly as it was authored.
    Remarks

    Light falls off with the square of distance, which is true and unusable on its own: it puts the outer planets at a few percent of the light the menu was lit and framed against, and the inner ones far past the top of the range. An eye does not work that way. Brightness is perceived closer to the fifth root of the square of intensity, so the physical figure is passed through that same response and what comes out is a picture that reads as further from the sun rather than one that reads as unlit.
