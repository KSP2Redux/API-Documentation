    Class ScatterShaderMapping

    Rebinds Redux stand-in scatter shaders onto their bundled base-game equivalents.

    Inheritance
    object
    ScatterShaderMapping
    Namespace: Redux.CelestialBody
    Assembly: Assembly-CSharp.dll
    Syntax
    public static class ScatterShaderMapping
    Remarks

    Scatter materials authored in this project cannot reference the base-game scatter shaders directly. Those shaders live in the ksp2.catalog AssetBundle and carry no AssetDatabase GUID, so a serialized reference to one cannot be written into a .mat asset. Materials therefore reference a Redux stand-in declaring the same properties, and the real shader is bound when Vegetation Studio builds its per item material copies. This mirrors what CelestialSimulationMaterialReplacer does for the surface material, except that the scatter path has no component of its own to hang the swap on, because the item prefab is never instantiated for the rendered field.

    Parameters
    Type Name Description
    string shaderName

    The shader name to translate.
    Returns
    Type Description
    string

    The base game name when shaderName is a Redux stand-in, otherwise the input unchanged.
    Remarks

    Pure name translation, resolved from the string alone, so it is safe to call from anywhere that reasons about shader names rather than shader objects. Shader controller selection needs exactly this: it runs against the name serialized on the material or the vegetation item, which is the stand-in, while the controllers match on the base game name.
