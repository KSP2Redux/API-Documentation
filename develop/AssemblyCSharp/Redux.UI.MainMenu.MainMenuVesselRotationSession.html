    Class MainMenuVesselRotationSession

    Runs the main menu's vessel rotation: picks a target, loads or builds it, shows it for a while, then moves on. Targets come from the loader's own addressable prefabs and from any OTA workspaces published, and the two are handled differently enough that most of this class is about keeping the difference invisible.

    Remarks

    Before OTA content this rotation only ever loaded addressables, so a load being in flight and the handle being valid were the same thing, and IAsyncHandleAccess consumers wait on exactly that. A workspace vessel is built rather than loaded and has no addressable operation behind it, so reporting nothing would leave those consumers waiting on a handle that only turns valid again when the rotation happens to land on a stock vessel, or never at all while the pool holds workspaces alone. The idle handle answers that honestly: there is nothing addressable left to wait for.

    UnloadForMenuClose()

    Takes the menu's craft down in an order that leaves nothing reading from a bundle as it closes.

    Declaration
    public IEnumerator UnloadForMenuClose()
    Returns
    Type Description
    IEnumerator

    An enumerator that finishes once everything has been released.
    Remarks

    Called by the loading flow while the curtain is up, on the way out of the menu, so the wait below costs nothing anybody sees. The order is the whole point:

    1. the craft stop being drawn, which is what stops the streaming system wanting more of them
    2. whatever it already asked for is allowed to finish, which is what this waits on
    3. only then are the parts released, closing their bundles with nothing outstanding
    Doing the last of those first is the version that fills the log: a menu craft's parts come from hundreds of bundles, their textures are streamed, and every read still in the air when an archive closes fails and is logged from a loader thread.

    Switching the craft off is not free either, since dropping a texture's mip level is itself a read, so it is done before the wait rather than after it.
